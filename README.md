# Lappland Music Player / 无序酒馆

在浏览器本地运行的沉浸式音乐播放器：拉普兰德站在半圆形吧台内侧，身后是一整面金色背光酒柜；每首歌是吧台上的一只实体酒杯，切歌时沿弧线传到你面前。Vite + React + TypeScript + Three.js，无音频上传服务，不请求任何外部网络资源（字体已随项目打包）。

当前仓库按所有者选择设为 **Private**，没有部署网站。MIT 适用于代码，不代表第三方角色图片也采用 MIT。

## 安装与运行

需要 Node.js 22.12+（推荐当前 LTS）及 npm。私有仓库克隆需要有访问权限并登录 GitHub。

```sh
git clone https://github.com/GoOdMAn5591/Lappland-music-player.git
cd Lappland-music-player
npm ci
npm run dev
```

打开终端显示的地址，默认 `http://127.0.0.1:5173/`。端口被占用时 Vite 会选择下一端口。日常使用请固定浏览器和地址：`localhost`、`127.0.0.1`、不同端口属于不同存储来源。

可以把整个项目文件夹复制到另一台电脑，再执行 `npm ci` 和 `npm run dev`。不需要复制 `node_modules`、`dist` 或机器专用路径。默认图片在 `public/assets/lappland/lappland-cutout-transparent.png`，应用使用支持 Vite base 的资源地址。

```sh
npm run build
npm run preview
```

`preview` 只是本地预览。本项目未配置 GitHub Pages、Vercel 或 Netlify。未来部署子目录可设置 `VITE_BASE_PATH=/Lappland-music-player/` 后构建，发布前再次审查素材权限。私有仓库不等于部署后的网站也私有。

## 一键启动（Windows）

双击项目根目录的 **`启动酒馆.bat`** 就行：

- 第一次运行（或 `package.json` 有更新）会自动 `npm install`；代码有更新时会先构建一次页面（`dist/`），之后秒开；
- 用 `server/tavern-server.mjs` 固定在 `http://127.0.0.1:5173/` 开门并自动打开浏览器（地址固定，浏览器里存的歌单和音频才对得上）；
- 酒馆已经开着时再双击，只会直接打开浏览器，不会再开第二个；
- 用的时候别关那个黑色窗口，关掉 = 打烊。

想在桌面放一个带酒杯图标的快捷方式，双击一次 **`创建桌面快捷方式.bat`**。两个 `.bat` 实际调用的是 `scripts/launch.ps1` 和 `scripts/create-shortcut.ps1`。

## 同席 · 和朋友一起听

1. 用「启动酒馆.bat」打开酒馆（开发模式 `npm run dev` 开不了房间）。
2. 右上角「…」→「同席 · 一起听」，填个称呼，点「开放同席」。
3. 第一次会自动下载 Cloudflare 官方的 `cloudflared`（约 20 MB，放在项目的 `tools/` 里，只下一次），然后生成一个 `https://….trycloudflare.com/?room=…` 邀请链接。
4. 把链接发给朋友。他们在任何地方用浏览器打开、填个名字点「入座」就行，不用装任何东西。

- 你的电脑就是酒馆：正在放的歌会从你的电脑传给在座的人，所有人按同一个时钟对齐进度（网速慢的人会先缓冲一下，再自动追上）。
- 在座的每个人都能点歌、播放 / 暂停、切歌、拖进度和换上酒方式；歌单、调酒笔记、添加歌曲只有房主能改。
- 只有拿到链接的人能进来（链接里带房间密钥）。每次开房都会换新链接；点「打烊」或关掉黑色窗口，房间就关闭。
- 刷新自己的页面不会关房间，朋友会留在座位上。
- 歌是从你的网络上传出去的：人越多、文件越大（FLAC / WAV），越吃上传带宽。
- 只适合和朋友私下一起听；请别把房间链接发到公开的地方。

手动启动服务器：`node server/tavern-server.mjs --open`（先 `npm run build`）。

## 语言与性能模式

- **中文 / English**：右上角「…」最下面一行切换。你自己的页面默认中文；朋友用英文浏览器打开同席邀请链接，会自动显示英文。歌名、歌单名等你自己填的内容不翻译。
- **性能模式**：右上角「…」→「性能模式」打开。适合配置低的电脑，或者一边打游戏一边挂着听歌：
  - 3D 吧台降到最低画质（关闭景深、泛光、抗锯齿），分辨率降低，限制在大约 20 帧；
  - 浏览器窗口失去焦点（比如切到游戏）或最小化后，3D 画面完全停止渲染，几乎不占显卡；音乐和同席照常；
  - 切回窗口、或鼠标移到窗口上，立刻恢复；
  - 同时关掉界面上耗资源的毛玻璃模糊和动画。

## 画面与操作

- **吧台**：真实 3D 半圆吧台（清漆木台面、黄铜包边与金线嵌条、酒红皮革嵌板、脚踏杆），身后是弧形酒柜：数百个带标签的酒瓶、镜面背板、层板灯带与壁灯，前景是酒红丝绒帷幕。整体有景深、Bloom、暗角与胶片颗粒。
- **酒杯**：每首歌一只杯（高脚杯、碟形杯、马天尼杯、古典杯、高球杯、白兰地杯、香槟杯、尼克诺拉杯、飓风杯），杯型与酒色由歌曲决定，也可以在「调酒笔记」里手动指定。液体有倾斜液面、波纹、气泡、金箔、杯底焦散光，当前杯会随低频/中频/高频起伏；切歌时杯子沿吧台圆弧滑动，液体有惯性晃动。
- **拉普兰德**：使用项目内授权 PNG（固定，不能替换），网格形变实现伪 Live2D——身体整体刚性地呼吸、轻微倾斜，头和双手作为整块转动，只有马尾、飘带和刘海会摆动，耳朵偶尔抖动，头部与视线跟随鼠标、眨眼、墨镜扫光；播放时她手中倒出的细流与杯中酒会变成当前歌曲的酒色。
- **点歌**：点击两侧酒杯即上杯（点当前杯 = 播放/暂停），悬停显示饮品卡；按住酒杯沿吧台拖动可调整顺序（触屏长按）。触屏左右滑动切歌。
- **进度与音量**：进度条是吧台前缘的金色刻度线，可点击或拖动；音量是右下角古典杯里的酒量，可拖动或滚轮微调。
- **酒单**：左侧「酒单」标签或右上角第一个按钮打开半透明酒单：歌单分区（新建 / 改名 / 撕下）、搜索、按菜单格式排列的曲目（时长像价格），拖拽排序，铅笔进入调酒笔记（别名、口味标签、杯型、酒色、所属歌单）。
- **右上角**：添加歌曲、导入 / 导出菜单 JSON、本地酒窖、角色构图（缩放、位置、动作幅度），以及「更多」里的同席（和朋友一起听）、Spotify 占位与 **画质（自动 / 高 / 中 / 低）**。自动画质会在掉帧时降低分辨率与景深。
- 快捷键：空格播放 / 暂停，左右键快退 / 快进 5 秒，Ctrl/Cmd+O 添加音频，Esc 收起酒单。系统开启「减少动态效果」时角色与镜头保持静止。

## 使用本地酒窖

- 首次打开可进入或跳过酒馆大门；跳过选择会记住，可在酒窖管理中重播。
- 点击上传图标或拖入音频。支持 MP3，WAV、OGG、FLAC 等由浏览器解码能力决定。metadata 失败会回退到文件名。
- 「本地酒窖」查看已存歌曲、音频与封面占用空间、持久化保护，删除单曲或清空酒窖。删除不影响电脑原文件。
- JSON 导入 / 导出保存歌单、排序、metadata、笔记与杯型 / 酒色选择，**不包含音频与封面 Blob**。跨电脑迁移请同时保留原音频并重新导入；原文件名、大小和修改时间共同用于匹配。完整音频备份包尚未实现。

音频 Blob、封面、metadata、歌单和编辑信息保存在 IndexedDB，启动自动恢复。导入申请 `navigator.storage.persist()`，浏览器可能拒绝。容量不足 / 禁用存储时退回会话播放与 metadata 尽力保存，并显示重新导入状态。清理网站数据、无痕会话结束仍可能失去内容，请保留原件。**GitHub 不会自动备份浏览器里的音乐库。**

## Spotify 歌单

把你 Spotify 里的歌单直接放上吧台播放，**不下载任何音频**：歌由 Spotify 直接播到浏览器里（Web Playback SDK），酒馆只知道曲名、封面和曲目编号。

**需要什么**

- **Spotify Premium**：网页里播放 Spotify 是 Premium 才有的功能（Spotify 的规定）。
- 一个你自己的 **Spotify 开发者应用**（免费，只建一次）。2026 年 2 月起，开发模式的应用拥有者也必须是 Premium，且**最多 5 个用户**。
- 电脑上的 Chrome / Edge / Firefox。

**第一次设置（约 3 分钟）**

1. 打开 [Spotify Developer Dashboard](https://developer.spotify.com/dashboard)，用你的 Spotify 账号登录 → **Create app**。
2. 名字随便填；**Redirect URIs** 填 `http://127.0.0.1:5173/callback`（一字不差）；**Which API/SDKs** 勾选 **Web API** 和 **Web Playback SDK**；保存。
3. 在应用的 **Settings** 里复制 **Client ID**，到酒馆里「更多 → Spotify 酒单」粘贴保存，然后点「连接 Spotify」。**不要复制 Client secret**——酒馆用 PKCE 登录，根本不需要它。
4. 想和朋友一起听：在应用的 **User Management** 里加上朋友 Spotify 账号的名字和邮箱。

之后在「Spotify 酒单」里选歌单点「放上吧台」，它会变成酒单里的一页（带 Spotify 标记），歌变成一只只酒杯。

**限制（Spotify 的规则，不是酒馆的）**

- 只能读取**你自己建的或你参与协作的**歌单的曲目，以及「我喜欢的歌曲」。别人的歌单 / Spotify 官方歌单：在 Spotify 里全选歌曲 →「添加到歌单」→ 新建一个你的歌单，再放上来。
- Spotify 歌单页的顺序跟着 Spotify 走；要加歌、调顺序请在 Spotify 里改，回来点刷新。
- 存档 / 导出的 JSON 里只记歌单链接，不存 Spotify 的曲目；每次打开酒馆会重新从 Spotify 取。
- Spotify 的歌不会驱动吧台的音乐律动（拿不到也不分析它的音频），封面和「在 Spotify 打开」链接会显示在吧台铭牌下方。

**同席时**：Spotify 不允许把一个人的音乐转播给别人，所以房主的电脑**不会**转发 Spotify 的声音。房间只同步「放哪首、到第几秒」，每位朋友在自己的浏览器里用**自己的** Spotify Premium 账号播放，酒馆把大家对齐（误差一般在 1 秒内）。朋友的步骤：入座 →「更多 → Spotify · 一起听」→ 登录 Spotify → 登录后小窗口会跳到一个打不开的 `127.0.0.1` 页面（正常）→ 把那个网址复制粘贴回酒馆。本地歌照旧由房主电脑转发。

开发者也可以把 Client ID 写进 `.env.local` 的 `VITE_SPOTIFY_CLIENT_ID`（见 `.env.example`）。技术细节见 [Spotify 设计](docs/spotify.md)。

## YouTube 歌单

不用任何账号，你和同席的朋友都不用。「更多 → YouTube 歌单」里粘贴链接：

- **歌单链接**（网址里带 `list=`）→ 变成酒单里的一页，最多读前 200 个视频；
- **单个视频链接** → 放进「YouTube 点歌」页，可以拖动排序、拿掉。

播放时吧台角落会出现一块 YouTube 小屏幕（手机上在顶部），可以放大或缩小。这是 YouTube 的规定，不是装饰：

- 播放器必须看得见、至少 200×200，不能只放声音，上面也不能盖东西；
- 广告由 YouTube 决定，酒馆不会拦截；
- 有些视频的作者不允许在别的网站播放，轮到时会自动跳过，酒单里标成「不能在别的网站播放」；
- YouTube 只允许应用把读到的资料保存 30 天，过期后那一页会清空，点「刷新」重新读取。

同席时，YouTube 视频不经过房主电脑：每个人的浏览器里都有同一块屏幕，酒馆把大家对齐到同一秒（误差一般在 0.5 秒内）。在屏幕里直接按 YouTube 自己的暂停、拖进度，全桌一起跟着变。有人看到广告时会稍微落后，广告播完会自动追上。

视频标题由酒馆的本地服务器向 YouTube 的公开 oEmbed 接口查询（浏览器不能直接查）；用 `npm run dev` 开发时没有这个服务器，标题会在第一次播放时补上。使用即表示同意 [YouTube 服务条款](https://www.youtube.com/t/terms)，并适用 [Google 隐私权政策](https://policies.google.com/privacy)。技术细节见 [YouTube 设计](docs/youtube.md)。
